# 3D箭头HOOK 制作流程

## 适用范围

分类名统一使用 `3D箭头HOOK`；`3D Arrow Hook`、`箭头迷宫3D动画`、`空心箭头物体动画`是检索别名。

用于把任意一张或一批图片转译为细箭头组成的三维镂空视觉。输入可以是照片、插画、人物、动物、交通工具、植物、产品、建筑、风景、抽象图形或已经完成的箭头迷宫图；输出可以是箭头化静帧、短视频，或先静帧后视频的完整链路。

目标不是把所有图片机械套上同一种纹理，而是先保留原图最重要的轮廓、比例、姿态、空间关系和色彩识别点，再用箭头方向场、密度和前后层次重建它。原图细节很多时允许有控制地简化纹理，但不能丢失主体身份和关键场景关系。

## 三种输入模式

先选择一种模式，不能把普通参考图错误当成已经完成的箭头尾帧：

| 模式 | 输入 | 标准流程 |
|---|---|---|
| `existing_arrow_art` | 原图已经是箭头迷宫或箭头线稿 | 直接把二维箭头结构解释为三维镂空主体，设计动作，最后压平回原图 |
| `arbitrary_image_arrowize` | 普通照片、插画或设计图 | 先生成并验收一张箭头化目标静帧，再用该静帧作为视频身份/尾帧参考 |
| `directed_arrow_target` | 普通源图加用户指定的箭头尾帧 | 源图负责主体语义与真实结构，箭头尾帧负责最终几何、配色和构图 |

`existing_arrow_art` 和 `directed_arrow_target` 通常属于 `directed_transition`。`arbitrary_image_arrowize` 若要求稳定尾帧，也应先完成箭头化静帧；只有用户明确接受开放式结果时才直接从普通图片生成视频，并说明无法保证精确的箭头布局。

外部生成仍受主技能授权边界约束。规划出箭头化静帧不等于获得提交图片生成或视频生成任务的授权。

快速路由：先看“三种输入模式”，普通图片继续看“任意图片的箭头化设计”，已有箭头图可直接看“逐图语义拆解”，需要实际生成时再看“批量执行流程”和“质量门”。

## 先冻结任务账本

批量生成前为每张图记录以下字段：

| 字段 | 作用 |
|---|---|
| `source_path` | 原图绝对路径 |
| `canvas` | 分辨率、画幅、透明通道、裁切情况和主体安全边距 |
| `source_type` | 照片、插画、已有箭头图、产品图、建筑图等 |
| `target_mode` | `existing_arrow_art`、`arbitrary_image_arrowize` 或 `directed_arrow_target` |
| `status` | `todo`、`reuse`、`redo` 或 `done` |
| `subject` | 动物、交通工具、物品或人物 |
| `objects` | 主体、陪体、承载物、环境元素的逐对象识别记录 |
| `scene_graph` | 对象之间的包含、接触、支撑、遮挡和动作关系 |
| `identity_anchors` | 必须保留的轮廓、比例、姿态、颜色与标志性部位 |
| `arrowization_scope` | 只转换主体，或主体与场景全部转换 |
| `supporting_scene` | 草坪、停机坪、叶片、雨线、水面等辅助场景 |
| `front_direction` | 头部或车头在画面中的左右方向 |
| `entry_edge` | 从哪侧进入画面 |
| `first_part` | 最先越过边界的部位，例如头、口鼻、前轮、机头 |
| `entry_mode` | 边界入场、远处靠近、原位展开或原位微动作 |
| `motion` | 与主体结构匹配的自然动作 |
| `animation_pattern` | 本片唯一主要动画模式及适用依据 |
| `tail_transition` | 到目标视角、目标姿态和二维尾帧的连续变换方法 |
| `arrow_target_frame` | 已验收的箭头化目标静帧；没有时标记 `待生成` |
| `tail_frame` | 必须对齐的尾帧；开放式结果可标记 `不要求精确尾帧` |
| `revision_base` | 首版、已接受版或指定版本 |
| `change_axis` | 本轮唯一或主要修改点 |
| `ambiguities` | 会影响提示词或动作设计的未决歧义 |
| `recognition_confidence` | 关键识别项的高/中/低置信度及证据 |
| `output_path` | 成品文件路径和版本名 |

用户说“做过的不用再做”时，先核验现有成品是否存在，再把对应项标记为 `reuse`；不要重新提交、重复扣费或仅凭记忆判断已完成。

## 精准图片识别协议

图片识别不是只输出一个类别名，而是为后续箭头化、动作和尾帧对齐建立可追溯的视觉证据。每张图都要区分三层信息：

| 证据层 | 定义 | 使用规则 |
|---|---|---|
| `observed` | 像素中可以直接看到的轮廓、颜色、位置、连接、遮挡和文字 | 只写视觉事实，不补故事，不把猜测伪装成事实 |
| `inferred` | 根据结构关系推断出的类别、朝向、动作功能或场景语义 | 必须同时记录依据和置信度；高影响低置信度推断不能直接进入生成 |
| `user_locked` | 用户明确说明或纠正的对象含义、方向、动作、颜色角色和版本要求 | 权限最高；后续返工持续冻结，除非用户再次修改 |

优先级为 `user_locked > observed > inferred`。文件名、同目录素材和历史成片只提供线索，不能覆盖当前图像像素和用户说明。颜色本身也不能单独证明语义：蓝色线条不天然等于水面或停机坪，绿色线条不天然等于草坪或叶片。

### 1. 多遍观察法

按固定顺序逐图观察，不能看一眼就直接写提示词：

1. **画布与输入质量**：记录分辨率、横竖画幅、透明背景、旋转方向、裁切、压缩伪影、文字/水印和主体安全边距；主体被裁断时明确哪些部位不可见。
2. **全局构图**：统计可辨对象数量，区分主主体、次主体、承载物和环境；记录各对象的归一化边界框 `[x_min, y_min, x_max, y_max]`、视觉中心、占画面比例和主要留白。
3. **局部拓扑**：沿轮廓检查部件如何连接，而不是只凭剪影命名。分别记录关键点、关节、开口、轴线、对称关系、重复结构和内部负空间。
4. **姿态与朝向**：记录主体朝向、身体/机身主轴、局部部件朝向、视角和判断证据。朝向必须来自口鼻、车把前叉、驾驶舱机头、开口或其他结构证据，不能只凭尾部外形猜测。
5. **深度与遮挡**：划分前景/中景/后景，记录谁遮挡谁、轮廓在哪些位置中断、对象是否真实接触、接触点和支撑边缘在哪里。
6. **颜色与材质角色**：提取主色、辅助色、环境色和轮廓色，区分对象固有色、光照色和背景色。除非实际取样，不伪造精确色值；箭头提示词优先写颜色角色和区域映射。
7. **关系与动作能力**：建立对象关系图，记录 `contains`、`attached_to`、`supports`、`touches`、`in_front_of`、`behind`、`approaches` 等关系；再判断可自然运动的关节、轮轴、旋翼、叶片、软组织和刚性部件。
8. **文字与标识**：只转录清楚可读的文字；模糊字符标成 `uncertain`，不得自行补齐。真实人物、商标或受保护角色仍按主技能的去标识化与保留边界执行。
9. **歧义复核**：列出所有会改变箭头化范围、入场顺序、动作或尾帧语义的歧义。能通过放大、裁切查看或检查相邻区域解决时先自行复核；仍无法解决时只问一个最关键的问题。

查看普通图片时，先用缩略图检查主体能否一眼识别，再以原尺寸或局部放大确认关键部件。已有箭头图还要逐个检查连通区域、箭头头部方向、断点、内部空隙、独立色区和轮廓闭合关系，防止把承载场景错并入主体。

### 2. 不同对象的关键识别点

| 对象类型 | 必须核对的局部证据 |
|---|---|
| 人物 | 头、躯干、左右上肢、左右下肢、手部、持物、视线、衣摆及脚与地面的接触 |
| 四足动物 | 口鼻、额头、耳朵、胸背线、肩髋、四肢、脚掌、臀部、尾根和尾尖；以口鼻所在侧定义“头先入场” |
| 鸟与昆虫 | 头胸腹、翅膀数量与开合、足部、触角/喙、预期落点；不能把翅或触角误作尾部 |
| 自行车与车辆 | 车把、前叉、前轮、车架、座椅、后轮、曲柄/动力部件和接地线；用前叉与转向结构确定车头 |
| 飞行器 | 机头/驾驶舱、机身、机尾、主翼或主旋翼、尾翼/尾桨、起落架和停机/跑道关系 |
| 产品与工具 | 主体外壳、开口、把手、按钮、盖体、工作端、可拆部件和部件从属关系 |
| 植物 | 容器、盆口、茎、叶根、叶尖、叶片前后层次、重力与生长方向；容器和叶片都要保持空心箭头结构 |
| 建筑与场景 | 地平线、地面、主要体块、入口、门窗、道路/基座、透视消失点和前中后景层次 |
| 抽象图形 | 连通分量、主轮廓、对称轴、重复单元、交叉点、开口、色区边界和视觉中心；不强行为其赋予具体物体名称 |

### 3. 标准识别账本

每个可辨对象至少记录以下字段；一张图有多个对象时逐对象建立记录：

```yaml
image_id: 文件名或稳定编号
object_id: 图内唯一对象编号
label: 对象名称；不确定时使用候选集合而不是强行定类
role: primary_subject | secondary_object | support | environment
bbox_norm: [x_min, y_min, x_max, y_max]
depth_layer: foreground | midground | background
pose_orientation: 姿态、朝向、主轴与视角
keypoints: 关键部件及位置
color_roles: 主色、辅助色、轮廓色、环境色及其所属区域
support_contact: 支撑物、接触点与接地状态
occlusion: 遮挡者、被遮挡者和轮廓中断位置
motion_affordance: 可动轴、关节、柔性部位与刚性限制
source: observed | inferred | user_locked
evidence: 支持该判断的可见结构或用户原话
confidence: high | medium | low
ambiguity: 尚未解决且会影响生成的歧义
```

同一对象可以有多条记录：例如“蓝色线条围绕飞行器”为 `observed`，“它是停机坪”为 `user_locked`。不要把二者合并成一个无证据的模型猜测。

### 4. 置信度与停止门槛

- `high`：至少两个相互一致的视觉结构证据，或用户已经明确锁定；可直接进入提示词。
- `medium`：主要证据成立，但局部被遮挡、过小或存在一个合理替代解释；提示词中只保留确定部分，并避免放大不确定细节。
- `low`：证据不足、候选解释互相冲突，或判断主要来自文件名、颜色、常识联想；不得把它写成确定事实。

如果以下任一字段为 `low`，暂停该单项的生成提交：主体数量、头/尾或前/后方向、承载物含义、关键接触关系、箭头化范围、必须对齐的尾帧结构。先放大复核；仍无法确认时，向用户提出一个带证据的定点问题。批量任务中只阻塞该图，其他识别清楚的图片继续处理。

### 5. 每图识别摘要

识别阶段先输出短结构化摘要，再写生成提示词：

```text
主体：1只哈士奇，正面坐姿（high：双耳、口鼻、胸部和两前腿均清晰）。
陪体/承载物：左侧卷曲尾巴与主体相连；无独立地面对象（high）。
箭头结构：主体由多个细线连通区组成，内部存在蓝/黄/橙/粉/青色箭头分区（high）。
朝向与入场：头部在上方中央；若横向入场，具体从左或右进入尚无像素依据（low）。
用户锁定：必须头部先进入，不能尾巴先进入。
待确认：横向入场边界未指定；若提示词需要指定方向，只询问这一项。
```

摘要中的每个关键结论都应能回溯到像素证据或用户原话。用户纠正过的内容写入 `user_locked`，以后不能因模型重新看图而自动改回。

## 任意图片的箭头化设计

### 1. 建立场景图，而不是只识别一个名词

把原图拆成：

- `primary_subject`：必须一眼认出的主要人物、动物、物品或建筑；
- `secondary_objects`：与主体动作或叙事有关的道具、承载物和陪体；
- `ground_or_support`：地面、叶片、停机坪、桌面、水面等承托关系；
- `environment`：天空、墙面、植被、室内空间、街道等；
- `negative_space`：必须保持通透的空隙；
- `text_or_logo`：只有用户明确要求保留且执行器适合时才纳入。

先决定 `arrowization_scope`：

- `subject_only`：只把主体箭头化，背景简洁或保持原样；
- `subject_plus_support`：主体和直接承载物箭头化；
- `full_scene`：主体、道具、地面和环境全部变成箭头场景。

用户没有说明时，根据原图识别重点选择最小充分范围：优先保证主体，再保留影响动作与空间关系的承载物，不把所有背景纹理都塞进箭头结构。

### 2. 提取身份锚点

不同输入至少保留以下信息：

| 输入类型 | 身份锚点 |
|---|---|
| 人物 | 外轮廓、姿态、头身比例、发型轮廓、服装大色块和手中关键物品；涉及真实人物时遵守主技能去标识化规则 |
| 动物 | 头部形状、口鼻、耳朵、躯干比例、四肢、尾巴和典型姿势 |
| 交通工具 | 车头/机头、轮轴或旋翼、驾驶舱、车架/机身比例和运动方向 |
| 产品 | 外形比例、开口、按钮、刷头、把手、部件从属关系和允许保留的文字区域 |
| 植物 | 容器轮廓、叶片数量范围、叶根到叶尖的生长方向和放射关系 |
| 建筑 | 天际线、入口、门窗节奏、主要体块、道路或基座关系 |
| 风景 | 地平线、前中后景层次、山脊/水岸/道路走势和主要光色 |
| 抽象图形 | 主轮廓、对称轴、重复节奏、色块边界和视觉中心 |

不要追求逐像素复制普通照片。箭头化目标应在缩略图尺寸下仍能认出主体，且关键空隙没有被箭头填死。

### 3. 把表面信息转成箭头方向场

用箭头的走向表达结构：

- 沿外轮廓布置闭合或连续箭头路径，锁定剪影；
- 沿肌理、生长方向、机械结构或透视消失方向布置内部箭头；
- 用箭头密度表达明暗和重要程度，亮部/主体可更密，次要背景更疏；
- 用颜色分区保留原图的大色块，不追逐噪点和微小纹理；
- 用前后错层、轻微视差和轮廓边缘光表达三维，不用实体壳体表达体积；
- 眼睛、轮毂、开口、门窗等关键负空间必须保留为空或用稀疏箭头界定。

### 4. 普通图片优先采用两阶段路径

当原图不是箭头设计时，质量优先流程是：

```text
普通参考图 -> 箭头化目标静帧 -> 静帧验收 -> 3D箭头视频 -> 尾帧验收
```

箭头化静帧至少检查：主体是否可识别、箭头是否细且分离、结构是否镂空、配色是否合理、场景关系是否正确、是否存在不需要的实体面。静帧未通过时先修静帧，不要直接进入昂贵的视频返工。

如果用户只授权写提示词，交付静帧提示词和视频提示词，停在 `prompt_package`。如果用户授权实际生成，先核验图片模型与视频模型的能力和费用，再分别提交。

### 5. 箭头化目标静帧提示词骨架

静帧提示词必须自包含，并用中文写清：

```text
参考职责：以输入图片锁定主体身份、外轮廓、比例、姿态、摄影角度和关键场景关系。
箭头化范围：明确只转换主体、主体加承载物，或整个场景。
结构转译：用大量细窄、均匀、互不粘连的箭头折线沿外轮廓、内部结构和透视方向搭出主体；箭头之间为空气。
身份锚点：列出必须保留的头部/车头、四肢/轮轴、产品部件、建筑天际线或其他关键部位。
颜色映射：把原图主色、辅助色和环境色映射到不同箭头区域，删除噪点和无意义小纹理。
三维表现：通过前后错层、轻微视差、疏密和边缘光表达体积，不生成连续实体面。
构图与背景：保持原图主体位置和安全边距；使用适合细箭头识别的简洁背景。
固定要求：主体一眼可识别；箭头细、空心、通透；关键负空间保留；不新增无关物体或随机文字。
```

如果原图包含大量文字、复杂 Logo 或精细 UI，先说明生成模型可能无法保持逐字准确。只有用户需要且执行器支持时才把文字作为必须保留项；否则优先保留版式和色块关系。

## 逐图语义拆解

### 1. 先读拓扑，再写方向

不要仅凭整体轮廓猜运动方向。分别识别：

- 动物：口鼻、耳朵、胸部、臀部和尾巴；
- 自行车：车把/前叉/前轮与车座/后轮；
- 直升机：机头、驾驶舱、尾梁、主旋翼和尾桨；
- 产品：瓶口、盖体、刷杆、工作端；
- 植物：盆底、盆口、叶根、叶尖。

方向必须写成完整三元组：

```text
主体朝向：车头朝左。
运动方向：从画面右侧向左移动。
入场顺序：朝左的前轮最先越过右边界，后轮最后进入。
```

只写“向左移动”仍可能生成倒退或尾部先入场；必须同时写朝向、移动方向和最先入场部位。

### 2. 给颜色分配场景语义

对已有箭头图，先把颜色区域分成 `主体`、`辅助场景`、`背景留空` 三类。对普通图片，先提取主体主色、辅助色和环境色，再把它们映射到箭头分区。周围箭头不能默认视为装饰背景。

已验证的典型关系：

| 图形关系 | 应解释为 |
|---|---|
| 自行车下方绿色线条 | 三维镂空箭头草坪或地表纹路 |
| 直升机四周与下方蓝色线条 | 同一座蓝色线条三维镂空停机坪 |
| 七星瓢虫周围绿色线条 | 瓢虫将要落下的绿色箭头叶片 |
| 雨衣人物周围竖线和脚下横线 | 雨线与水面波纹 |

如果用户纠正语义，以最新说明为准。不要把“停机坪”自动扩写成“先升起、再降落”，也不要把“叶片”改成普通绿色背景；场景是什么与场景何时运动是两个独立变量。

### 3. 区分主体、承载物和环境

复合场景至少写清：

- 主体从哪里来；
- 承载物从第一帧存在还是需要形成；
- 主体与承载物的接触点；
- 接触后的回弹、停稳或悬停；
- 两者如何共同压平到尾帧。

例如“七星瓢虫飞到叶子上”必须出现飞行、减速、六足依次接触绿色叶片、轻微回弹、翅盖闭合和停稳，不能只让瓢虫在叶子旁悬停。

## 三维箭头视觉约束

无论原图是照片还是箭头线稿，`3D` 都表示箭头线条在空间中具有前后层次，不表示给主体增加连续表面或传统实体材质。优先使用正向结构描述：

```text
主体完全由空间中排列的细窄彩色箭头折线搭成。
箭头之间全是空气，只有线条、箭头头部和前后层次。
花盆、叶片、车体或动物轮廓都保持空心、通透和非实体状态。
```

只在固定要求中保留一句短限制：

```text
全片只显示细箭头线条和空气间隙，不出现连续实体面或块状模型。
```

箭头粗细是一级质量参数。默认写明 `细窄、均匀、边缘清楚、互不粘连`，并避免发光过强导致相邻箭头视觉上熔成粗线。复杂照片需要通过减少箭头数量和优化方向场来保持清晰，不能靠加粗线条解决拥挤。

## 可迁移的动画效果库

以下模式来自已观察参考片的动画表现。只学习运动语法、节奏和三维到二维的处理，不复用参考片中的具体主体、配色、构图、背景、文字、水印、品牌或关卡设计。每条视频默认只选择一个主要模式；用户指定动作时以用户要求为准，不能为了套模式改变主体语义。

| 模式 | 可观察动画效果 | 适合对象 | 执行重点 |
|---|---|---|---|
| `layered_unfold_to_plan` | 紧凑的三维形态原位展开，多层部件错时向外、向上舒展，形成完整体积后转到目标正视/俯视角，再压平成二维图案 | 花朵、折叠结构、层叠物、放射或环形图案 | 从外层到内层或按真实铰接关系错峰展开；每层走弧线，不同时机械张开；展开完成后才进入平面化 |
| `articulated_flight_to_profile` | 主体持续飞行，左右翼交替经历抬升、下压和回收，身体随拍翼轻微升沉、俯仰并绕垂直轴转向，最终到目标侧面或指定视角 | 鸟、昆虫、带翼角色或飞行器 | 翼根先驱动、翼尖略滞后；转向来自身体轴与双翼推力配合；接近目标姿态时逐周期减小振幅，不能突然停翼 |
| `micro_pose_to_portrait` | 主体基本原位，只做头部小幅转正、肩部反向补偿、轻微呼吸和附属部位延迟摆动，摄影机或主体缓慢后退以露出完整构图，最后定格 | 人像、半身角色、已经接近尾帧的正面主体 | 幅度小于身份锚点容许范围；脸部、五官和轮廓不能漂移；用微动作建立三维感，不强加走路或大旋转 |
| `distant_approach_orbit_to_target` | 主体从画面深处以小尺寸出现，沿纵深靠近并逐渐放大，在中央悬停或绕自身轴展示多个角度，最后转到尾帧要求的目标视角 | 小型飞行主体、悬浮物、需要展示立体结构的物件 | 靠近包含真实透视缩放、轻微升沉和减速；绕轴展示控制在一个清楚方向，不能左右来回乱摆；先结束旋转再压平 |
| `gait_yaw_to_silhouette` | 主体以自然步态运动，四肢交替承重，身体轻微上下起伏，同时逐渐转到尾帧所需的侧面或正面，减速停稳后变成二维轮廓 | 四足动物、双足角色、轮式交通工具的等价滚动版本 | 步态相位、落脚点和移动方向一致；头部/车头先导，耳朵、尾巴或悬挂件做次级延迟；转向不能导致倒退或滑步 |

### 动画模式选择规则

- 先看拓扑和可动结构，再选择模式。层叠/放射结构优先原位展开；带翼主体优先关节飞行；人像优先微动作；四足主体优先步态；需要展示立体结构但没有明显关节的对象可使用受控靠近加单向绕轴。
- `entry_mode` 与 `animation_pattern` 分开记录。参考片证明主体不一定必须从画外进入，也可以从远处靠近、原位展开或原位微动；但用户明确要求“头部先入场”时仍必须采用边界入场，并锁定头部为第一越界部位。
- 不把多个模式全部叠加。比如已经采用完整飞行拍翼和转向时，只允许一次简洁的绕轴或靠近，不能再加入展开、弹跳和大幅镜头环绕。
- 目标尾帧决定最后的视角和姿态。动画展示可以经过正面、背面或三分之四侧面，但在压平前必须先回到尾帧对应的正视、侧视、背视或俯视。
- 没有真实关节的物品不套用动物动作；没有层叠结构的主体不强行开花式展开。无法从图片确认结构时，选择幅度更小的模式。

### 运动层级与节奏

1. **根运动先行**：先确定主体整体的位移、旋转或展开轴，再让翅膀、四肢、叶片、头发和尾巴等次级部件跟随。
2. **相位错开**：成对肢体或多层部件不能同时同幅运动。用轻微时间差产生自然的重量感和弹性，但不能破坏最终图案的连接关系。
3. **展示后收束**：主要动画占据前段；进入尾帧前先减速、减小摆幅、锁定目标视角和目标姿态，再压缩三维深度。
4. **深度压平**：同一组箭头的 `z` 轴层次、透视差和遮挡差连续归零，轮廓和颜色区域逐步对齐目标图案。不得用透明度淡化、溶解、硬切或换图冒充压平。
5. **尾帧静止**：摄影机先稳定，附属部件在一至两个动作周期内停下，二维尾帧保持足够时间供肉眼识别和后续拼接。
6. **环境反馈可选**：地面反射、接触阴影或粒子只能用来说明距离、落点或速度；尾帧没有这些元素时，应在压平前自然减弱，不能成为新增场景内容。

推荐把五秒动画分成 `动作展示 -> 目标视角/姿态对齐 -> 三维深度压平 -> 二维尾帧保持` 四个连续阶段。动作幅度可以变化，但四阶段顺序不要倒置；尤其不能在主体仍背对错误方向或肢体仍大幅运动时直接压平。

## 动作设计

动作必须服从原图主体的真实结构，但幅度要小，避免破坏身份锚点。普通图片没有明确运动时，根据主体类别选择一个主要动作，不同时塞入多个戏剧事件。

| 类型 | 推荐动作 |
|---|---|
| 人物或角色 | 保持身份锚点与身体比例，选择自然走入、转身、抬手或定姿中的一个主要动作；手部和衣摆只做小幅次级运动 |
| 四足动物 | 头部先入场，前后腿交替，肩髋轻微起伏，耳朵或尾巴做次要动作 |
| 自行车 | 车头朝向与运动方向一致，车轮滚动，曲柄与脚踏同步，减速刹停 |
| 直升机 | 机头先入场，主旋翼和尾桨同步旋转，机身轻微前倾，中央悬停 |
| 飞虫与叶片 | 叶片稳定或轻摆，昆虫飞入、减速、落到明确接触点并收翅 |
| 盆栽 | 箭头线条组合成盆体与叶片，叶片小幅错时摆动，不生成实体花盆 |
| 产品组件 | 保持部件从属关系，例如刷杆从瓶口抽出后移动到尾帧位置 |
| 人物场景 | 人物自然步入；雨伞、衣摆、雨线和水面只做与动作相关的次级运动 |
| 建筑 | 箭头沿地基、立面和天际线依次组装，或做极小幅视差环绕；建筑本体不软化、不弯曲 |
| 风景 | 沿山脊、水岸、道路和地平线建立前中后景；只让云、水流、风或光流产生局部运动 |
| 抽象图形 | 沿对称轴、重复节奏或主轮廓有序组装、旋转或展开，最终恢复稳定几何 |

不要为“画面更丰富”增加用户没有要求的事件。用户说“在第一版基础上只增加蓝色停机坪”时，冻结第一版的飞行方向、节奏和悬停动作，只添加停机坪的空间语义与视觉描述。

## 五秒节拍模板

下面是可调整的基线，不是所有项目的硬编码：

| 时间 | 功能 |
|---|---|
| `0.00–约1.70秒` | 按 `entry_mode` 执行边界入场、远处靠近、原位展开或原位微动作；承载场景按用户要求从首帧存在或自然形成 |
| `约1.70–2.90秒` | 完成所选主要动画模式；根运动清楚，关节或分层部件按相位跟随 |
| `约2.90–3.60秒` | 减速并对齐尾帧的目标视角、姿态、轮廓和主体位置，只保留逐渐衰减的次级动作 |
| `约3.60–4.10秒` | 同一组箭头的三维纵深、透视差和遮挡差连续归零，逐层对齐箭头化目标帧 |
| `约4.10–5.00秒` | 箭头化二维尾帧稳定静止；开放式结果可改为稳定的三维定姿 |

需要精确尾帧时，不要用淡化、溶解、遮罩或硬切伪造衔接。压平阶段应描述为同一组箭头的纵深逐渐归零，而不是换成另一张图。普通原图若未先制作箭头化目标帧，不得声称能精确对齐某个未知箭头布局。

## 提示词写法

仍遵守主技能的七段式输出契约。对本类别特别补充：

1. `生成规格`：写时长、画幅、分辨率、单镜头和声音策略；按输入模式说明普通原图与箭头目标帧分别承担什么职责。
2. `主体与场景`：分别定义身份锚点、箭头化范围、主体、承载物、环境和颜色语义。
3. `摄影机与构图`：写固定机位，以及朝向、运动方向、入场边界和入场顺序。
4. `视觉风格`：写纯细箭头、空心、通透、前后层次，以及原图色彩如何映射到箭头；避免实体材质。
5. `时间轴`：覆盖组装或入场、自然动作、停稳、压平和尾帧静止；开放式结果可以用稳定三维定姿收束。
6. `声音与台词`：无口播时写 `subtitles: off`；是否生成音频由用户要求和执行器能力决定。
7. `固定要求`：只保留方向、主体数量、箭头形态和关键场景关系。

## 批量执行流程

1. 枚举输入目录中的图片，并为每张图建立任务账本。
2. 逐图按“精准图片识别协议”建立对象记录、场景图和每图识别摘要；禁止只按文件名、颜色或整体剪影猜内容。
3. 对主体数量、朝向、承载物、接触关系和箭头化范围执行置信度门槛；高影响低置信度项只阻塞对应图片。
4. 标记 `reuse`、`redo` 和 `todo`；先跳过已有合格静帧或成片。
5. 对普通图片先生成并验收箭头化目标静帧；已有箭头图可跳过这一步。
6. 为每个 `todo` 或 `redo` 项写独立、自包含的七段式视频提示词。
7. 选择执行器时读取对应能力契约；使用 Seedance 2.5 时同时读取 `seedance-2.5-prompt-guide.md`。
8. 提交前做 dry-run 和费用核对；批量任务保存索引到任务 ID 的映射。
9. 按精确任务 ID 等待和取回输出，不用“最后一个任务”推断结果。
10. 先下载到临时或版本化文件名，确认文件存在、大小非零且媒体容器有效，再更新标准成品名。
11. 最终核对源图、箭头化静帧与标准成品数量；报告新生成、复用、失败和实际费用。

执行器只返回“任务完成”不等于视觉验收通过。条件允许时至少检查开场、主体入场中段、停稳帧和尾帧四个位置。

## 定点返工与版本管理

### 一次只改一个主要变化轴

把返工写成：

```text
revision_base: v1
freeze: 飞行方向、入场动作、悬停节奏、摄影机、时长、尾帧
change_axis: 四周蓝色线条解释为三维镂空停机坪
```

从 `revision_base` 的完整提示词重建新版，不从最近一次失败稿继续累积修改。用户说“第一版基础上”时，必须读取第一版原提示词；不能把第二版新增的“停机坪升起”和“直升机降落”带入第三版。

### 安全替换

- 新输出先保存为 `_vN.mp4` 或其他临时文件名；
- 验证后再更新标准名 `原图名_3D箭头动画.mp4`；
- 替换前检查标准文件和目标备份是否真实存在，不凭历史记录假设；
- 旧版仍需保留时改名为 `_v1.mp4`、`_v2.mp4`；不存在旧版时直接放置新版并如实报告；
- 只处理本轮获准返工的文件，其他成品不移动、不覆盖。

- [ ] 已以原尺寸或必要的局部放大查看源图，裁切、遮挡和不可见区域已记录；
- [ ] `observed`、`inferred` 与 `user_locked` 已分开，用户纠正项已经冻结；
- [ ] 主体数量、对象边界框、前中后景和主要留白已记录；
- [ ] 关键部件拓扑、主轴、朝向及其视觉证据已记录；
- [ ] 支撑、接触、遮挡和部件从属关系已建立场景图；
- [ ] 文件名和颜色没有被当成唯一语义证据；
- [ ] 会影响生成的低置信度歧义已解决，或该单项已暂停而非被强行猜测；
- [ ] 主体的头部/车头和尾部已识别；
- [ ] 已选择正确的输入模式，普通图片不会被误当成箭头尾帧；
- [ ] 身份锚点和箭头化范围已冻结；
- [ ] 普通图片的箭头化目标静帧已生成并验收，或用户明确接受开放式结果；
- [ ] 朝向、运动方向、入场边界和最先入场部位互相一致；
- [ ] 每个颜色区域已分配为主体、承载场景或背景留空；
- [ ] 纯细箭头、镂空、非实体要求已写成正向结构描述；
