# 参考视频复刻工作流

## 状态机

| 状态 | 必备证据 | 允许动作 | 退出条件 |
| --- | --- | --- | --- |
| `INTAKE` | 用户原始需求 | 补齐阻塞参数 | 素材、目标和模式明确 |
| `PREFLIGHT` | 可访问素材 | 读取媒体信息 | 素材可分析 |
| `ANALYZE` | 已核验素材 | 建立镜头、台词、叙事账本 | 原片结构完整 |
| `REWRITE` | 三份原片账本 | 替换矩阵与逐镜方案 | 每项变更可追溯 |
| `VARIANT` | 冻结的核心脚本与变体规则 | 变体矩阵、独立 Prompt 和不变校验 | 每个变体只改获准轴 |
| `SEGMENT` | 完整逐镜方案 | 划分生成片段 | 边界、时长和声音一致 |
| `CAPABILITY` | 候选执行器 | 核验参考图、首帧、参数和结果能力 | 执行路径可行 |
| `REVIEW` | 完整方案 | 用户修改或确认 | 获得明确确认 |
| `REFERENCE` | 已确认场景设定 | 生成并核验全景参考图 | 实际图片已锁定 |
| `GENERATE_SEGMENT` | 参考图；连续段还需前段尾帧 | 只生成当前片段 | 结果可查看 |
| `HANDOFF` | 当前片段验收通过 | 提取并核验实际尾帧 | 交接帧就绪 |
| `ACCEPT` | 全部结果与接缝可查看 | 最终验收和定点返工 | 全部门槛通过 |

内容修改后从 `REWRITE` 重新计算；`variant_package` 在 `REWRITE -> VARIANT -> SEGMENT` 间为每个变体独立计算。执行阶段在 `GENERATE_SEGMENT -> HANDOFF -> GENERATE_SEGMENT` 间串行循环。

## 核心脚本与多个变体

当输入是完整脚本而不是参考视频，先把脚本拆成稳定的核心账本，再生成变体。`dialogue_texts` 保存原台词文本；冻结模式下变体不允许填写对白覆盖。最小结构如下：

```text
core_script:
  frozen: true
  beat_ids: [B01, B02, B03]
  dialogue_ids: [D01, D02]
  dialogue_texts: {D01: "原台词一", D02: "原台词二"}
  invariants: [plot_order, dialogue_order, product, cta, duration_envelope]
variant_policy:
  count: 3
  allowed_axes: [setting, wardrobe, camera_style]
  forbidden_axes: [plot_order, dialogue_order, product, cta]
  max_changed_axes_per_variant: 1
variants:
  - id: V01
    changed_axes: [setting]
    delta: {setting: "..."}
    preserved_core_ids: [B01, B02, B03, D01, D02]
```

“变体”只表示在 `allowed_axes` 内做可归因的替换；改变因果顺序、删掉核心节拍、添加新的产品承诺、重写 CTA 或改变台词意图都不是变体。每个变体都从冻结版复制一份完整脚本后应用自己的 `delta`，不能从另一个变体继续修改。

长脚本先固定核心脚本的分段边界，再复制这套边界到每个变体。只有变量导致时长超限时才重新分段，并在输出中说明原因；每个变体仍单独执行场景参考图与尾帧接力。

## 变体提示词交付

默认交付模式是 `direct_variant_prompts`。每个变体都必须提供完整、独立、可直接粘贴的 Prompt，而不是只提供 `delta`：

```text
V01 | 变化轴：场景
核心不变：B01/B02/B03；D01/D02；CTA
完整视频 Prompt：
<固定参数 + 完整动作/台词 + V01 场景 + 摄影/光线/声音/负面约束>
```

Prompt 必须把固定剧情和本变体变化写全，不能依赖用户同时查看核心脚本或其他变体。若脚本需要分段，则每个变体下分别列出完整的 A、B、C 片段 Prompt；连续片段注明场景参考图 ID、上一段尾帧作为首帧，以及不可重置的姿态/构图/道具状态。

## 输入契约

分析至少需要：

- 参考视频、本地文件、可访问 URL、已有素材节点或完整脚本之一。
- 一句明确目标，例如“保留剧情结构，替换人物、场景和产品”。

生成前还需要：

- 画幅、分辨率、语言和声音要求。
- 未指定时采用的默认地域、对白语言、色彩基线和真人摄影基线：欧美地区、英语、丰富鲜艳但不溢色、奥斯卡级/好莱坞叙事摄影的可执行特征。
- 台词、产品、品牌和 CTA 最终版本。
- 片段上限；默认 `15s`，不得超过执行器上限。
- 场景参考图方案。
- 已核验的执行器能力。
- 用户明确生成确认。

缺失项可先用 `待确认`，但不得用推断替代会改变成片的选择。

默认基线只作用于新生成或改写内容。用户明确指定、冻结的 `core_script` 和原片可验证事实优先；原片账本不能因为默认欧美语境而改写成欧美来源。

## 台词和声音交付

只要镜头中有人说话、旁白或画外音，方案必须交付逐句 `dialogue_delivery_sheet`，并把同一文本写入逐镜 Prompt 和分段 Prompt。每句至少包含台词 ID、镜头 ID、说话人、准确文本、语言/地区变体、时间范围或可用时长、表演方式、声音路径、唇形同步、字幕开关、字幕位置和样式。

生成或改写模式默认把新台词写成自然当代英文；原片听不清的对白在 `analysis_only` 中只能标记 `待确认`，不能编造。若改写模式需要起草英文台词，先保留原意并标记待确认，确认门前不得提交外部生成。没有对白的镜头写 `无对白`，同时给出环境音、音效、BGM 和字幕策略。

字幕优先级：用户最新明确要求显示字幕时，覆盖更早 Prompt 中的“不要字幕/不得出现字幕”约束；完整 Prompt 必须明确 `subtitles: on`、逐句字幕文本、下方安全区位置和样式。下方留白默认解释为字幕安全区，而不是关闭字幕。若用户没有明确字幕要求，保留已确认设置；出现冲突时列为待确认，不得静默选择无字幕。

口播容量按镜头时长检查，常规自然对白先按约 `2.0-2.8 words/s` 估算；超出时缩短、延长或标记待确认。字幕开启时，逐句字幕必须与最终台词逐字一致。禁止用“自然对话”“同上”“延续上一句”或省略号代替完整台词或字幕。

## 原片账本

为镜头分配 `S01`、`S02`，为台词分配 `D01`、`D02`，原始顺序不变。

```text
Shot S01 | 00:00.000-00:04.800 | 4.8s
剧情功能：开场/钩子/冲突/升级/反转/产品/CTA
动作调度：人物、动作、道具、空间关系
摄影：景别、机位、方位、路径、速度、稳定度、焦点、景深
光线与风格：时间、主光、色彩、曝光、质感
声音：台词 ID、环境音、音效、BGM
屏幕元素：字幕、Logo、产品 UI、贴纸
不确定项：待确认列表
```

台词账本：

```text
D01 | S01 | 人物A | <原始台词>
D02 | S01 | 人物B | <原始台词>
```

生成台词交付表：

```text
D01 | S01 | Speaker A | English/en-US | <完整台词> | 00:00.500-00:03.200
表演：<情绪/重音/停顿/音量> | 声音：<原生或后期> | 唇形同步：yes | 字幕：<同文或 none>
```

新写或改写的对白必须填满 `<完整台词>`，并在逐镜和片段 Prompt 中逐字保持一致。真人镜头默认使用丰富、鲜艳、受控的综合色彩，且把导演参考转译为具体焦段、机位、运动、调度和动机光。

## 替换矩阵

| 元素 | 原片 | 新版本 | 动作 | 用户确认 |
| --- | --- | --- | --- | --- |
| 人物 | 原人物 | 新人物设定 | 替换 | 是/否 |
| 场景 | 原地点 | 新地点 | 替换 | 是/否 |
| 产品 | 原产品 | 新产品 | 替换 | 是/否 |
| 叙事结构 | 原因果链 | 新版本 | 保留/替换 | 是/否 |

每轮修改都从原片账本和已确认替换矩阵重建完整方案，不在旧 Prompt 上累积局部补丁。

## 分段算法

1. 按原片时间顺序遍历镜头。
2. 检查场景、人物、时间、动作和情绪是否连续。
3. 合并后时长不超过 `min(15s, 执行器上限, 用户上限)` 时加入当前片段。
4. 遇到空间跳转、时间跳转、情绪断点或超时，在自然叙事节点断开。
5. 分配稳定顺序 ID：`A`、`B`、`C`。
6. 为每段生成完整 Prompt 和依赖关系。

分段只改变生成单位。没有明确授权时，不压缩剧情、不删台词、不改变节拍。

## 场景参考图

每个连续场景建立一张实际全景参考图 `R01`、`R02`，锁定：

- 人物身份、身材比例和完整服装
- 固定与随身道具
- 环境结构、出入口和主要行动路线
- 人物初始方位、时间、天气、主光和色温

参考图使用稳定全景，人物清晰，无瞬时动作、遮挡、运动模糊、字幕或水印。同场景沿用同一张图片；关键设定变化时新建参考图，不能覆盖旧基准。

## 尾帧接力

```text
R01 -> A -> 验收 A -> A_tail
R01 + A_tail 作为 B 首帧 -> B -> 验收 B -> B_tail
R01 + B_tail 作为 C 首帧 -> C
```

执行规则：

1. 确认当前参考图为实际可访问资产。
2. 确认前段是验收通过版本。
3. 从前段末尾附近提取最后一张清晰稳定的有效帧。
4. 记录来源视频、时间点、文件路径和哈希。
5. 把同一尾帧文件原样设为下一段首帧输入。
6. 下一段第一帧继承姿态、视线、手部、道具、方位、机位、光线和运动方向。
7. 验证执行器确实接收了参考图和首帧，再提交生成。

双参考冲突时：尾帧决定首帧构图与动作起点；场景参考图决定人物身份、服装、固定环境、道具样式和光线基准。无法同时满足时停止并修正资产。

## 场景切换

同场景连续片段必须尾帧接力。明确空间或时间跳转时使用 `hard_cut`：

- 记录切换原因。
- 建立新场景 ID 和新参考图。
- 新场景首段不继承旧场景尾帧。
- 跨场景继续出现的人物仍继承已确认的人物设定。

## 交付格式

方案阶段：参数摘要、默认基线实际取值、原片镜头表、完整台词表、`dialogue_delivery_sheet`、叙事账本、替换矩阵、逐镜方案、分段方案、场景参考图提示词、执行器能力表、尾帧依赖表和待确认项。

执行阶段逐段交付：当前参考图、当前片段结果、验收结论、实际尾帧、提取时间点、下一段输入资产。

最终交付：全部片段顺序、每个接缝结论、整体剧情与参数验收、需要返工的片段 ID 和单一修正目标。
